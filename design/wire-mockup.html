Giving coding agents a persistent memory layer, and why it changes how you prompt them

Most agent frameworks treat every session as a blank slate. I've been experimenting with a small SQLite-backed memory layer that survives between runs, and it changes the way you write instructions almost immediately — you stop re-explaining project conventions in every prompt.

The interesting failure mode isn't forgetting — it's confident misremembering, where the agent applies a convention from a different project because nothing distinguishes the two in its context. Namespacing memories per repo root fixed most of it.

The rough shape: on session end, summarize decisions into a handful of short entries tagged by file path and topic; on session start, retrieve the ones whose tags overlap the current working set. It's grep, basically, with extra steps.
